01 · DATACollecting and cleaning the corpus

None of this is a downloaded dataset. The restaurants come from public map data, the labels are a much larger model's own agentic trajectories, and the web pages those trajectories read are captured as they are fetched — so any run can later be replayed against the same bytes.

Grounding is the gate that earns its keep. Every extracted item is matched back against the text the agent actually scraped during that episode, so a trace under 40% grounded is a trace that invented food, and it leaves. What survives averages 0.98.

02 · TRAININGContext distillation, not prompt copying

The naive version of this stage captures the teacher's trajectories and trains on them verbatim. That bakes in a dependency: the targets are only correct given a prompt full of guidance the student would then also need at inference, so the work has moved into the prompt rather than into the weights.

So the prompt is split in two. Anything that defines what the right menu is — the schema, the food-only scope rule, the tool declarations, the diner's dietary restrictions — is identical for both models. Anything that only shapes how the agent works — try the plain fetch before the browser render, don't give up after one search, confirm the page is the same restaurant, prefer the restaurant's own site over a delivery app — is teacher-only, and the student has to learn it from the trajectories themselves.

The failure this fixed was termination, not menu quality. The student's dominant error was emitting nothing at all — it would gather evidence and never commit to an answer. Its menus were already teacher-quality when it finished. A single prompt rule forbidding the empty reply moved success from 56% to 88% and empty output from 38% to 12% on the same episodes: 16 episodes fixed, none regressed. Diagnosing that before reaching for more training saved the budget that would have gone into it.

03 · WEIGHTSFrom adapter to something servable

A trained adapter is not yet a served model. The two conversions between them are both easy to skip, and both fail in ways worth knowing about in advance.

04 · INFERENCEOne request, and where the cache sits

At inference the model is an agent on a budget: eight tool calls, then it has to answer with whatever it has gathered. A partial menu beats an empty reply — and it also makes better training data than a refusal.

The cache is the piece worth drawing, because its position is the design. It wraps the network backends inside the character cap, so what gets stored is the full slimmed page while the cap stays a read-time knob that can be retuned without re-scraping anything.

Each turn re-renders the prompt from the whole message list, which is only safe because Gemma 4's template is token-prefix-preserving for this shape of trajectory: rendering the first k messages is an exact prefix of rendering k+1. That property is what lets the training mask be computed by hand, and it is also why a parse failure is fed back as a synthesized tool response rather than a new user turn — a mid-episode user message rewrites earlier tokens and breaks the prefix.

05 · CONTRACTThe output schema

One file defines the menu shape, and the prompt, the validator, the grounding scorer and the RL reward all import it, so they cannot drift apart. It is deliberately small: two levels of nesting, three fields on an item.
